次の順で進めてください。

1. README_jp.md を読み、続けて docs/01-php2shell.md と docs/02-nodejs-oct2026.md を読む。
   バージョンの対応表と緩和策は、この3つのファイルだけを根拠にすること。
   記憶から CVE や影響バージョンを補わない。

2. まず読み取り専用で実行し、生の出力をそのまま見せること:
     tools/php2shell/bin/p2s-audit --json
     tools/node/nodefix-audit
   --target <ssh-host> は、私が名前を挙げたホストにだけ付ける。

3. README_jp.md の「2-3. 判定」の表のとおりに分岐する。
   出力がどの行にも当てはまらない場合は、推測せず止まって報告する。

4. 変更の前に、必ず --dry-run で実行して計画を見せること。私の承認を待つ。
   複数ステップをまとめて承認扱いにしない。

5. 変更のたびに README_jp.md の「2-5. 検証」で確認する。コンテナ再起動を跨ぐ確認も含める。
   バージョン文字列だけで成功と判断しない。

6. 最後に次を報告する:
   - 見つかったもの（実行中のバイナリから読んだバージョン付き）
   - 変更したもの（使ったコマンド付き）
   - できなかったこと、その理由
   - 残っている作業
   部分的な緩和を「修正」と表現しないこと。

守ること。
- 私が名前を挙げたホスト以外に触れない。第三者のシステムにスクリプトを向けない。
- 認証情報はリポジトリに無い。必要なら私に聞く。推測したり探し回ったりしない。
- PHP の暫定策は設計上「部分的」である。部分的な箇所は「部分的」と明記する。
- 分からないことは「分からない」と書く。もっともらしい文章で埋めない。
