OpenHands SDK: unauthenticated command execution in publicly exposed sandbox agents.

The CNA record for CVE-2026-112346 describes unauthenticated sandbox command execution with empty session_api_keys in SDK versions below 1.52.0. If the exposed port is reachable, root inside the sandbox and mounted workspaces and secrets are affected. The reviewed PR #5209 restricts DockerWorkspace host-side port exposure to 127.0.0.1 while retaining the 0.0.0.0 listener inside the container. This PR does not establish that the same fix applies to Apptainer, which the CNA also lists.

What to checkCheck fixes in software-agent-sdk 1.52.0 or later, recreate workspaces, and verify host port exposure and session key settings. Do not judge whether the SDK launcher fix is applied solely from the agent-server image tag. Separately investigate logs and revoke/reissue secrets from workspaces that were reachable.

03:17 JST (NVD published) · Caveats on CNA records and prerequisites.

Consul: authorization bypass for cached leaf certificates and private keys

CVE-2026-105765 affects Consul 1.17.0–2.0.4 with ACLs enabled. Cached service leaf responses from the agent HTTP API lack ACL token checks, allowing a reachable attacker to obtain already cached certificates and private keys under the applicable conditions. By default, the API listens only on loopback, limiting exposure to processes on the same host. This does not mean keys for every service can be obtained unconditionally.

What to checkCheck Consul Community 2.1.0 and Enterprise 2.1.0 / 1.21.19 by release branch. Investigate agent API access restrictions and service identities and certificates that may have been exposed. Consider blocking the leaf endpoint only if Connect-native applications and consul-template do not depend on it.
