OpenTelemetry (JS / Go / Python): unredacted server-span query strings, attribute-length bypass and header parsing

In JavaScript, `@opentelemetry/instrumentation-http` (CVE-2026-128080) redacts sensitive URL query parameters on outgoing client spans but writes the raw query string verbatim into `url.query` on incoming server spans, exposing presigned URLs, SAS tokens and API keys in telemetry backends. In Go, valid U+FFFD runes bypass `AttributeValueLengthLimit` (CVE-2026-128085) and W3C baggage parsing causes disproportionate memory allocation (CVE-2026-128086). In Python, `opentelemetry-api` (CVE-2026-126360) suffers quadratic-time ReDoS on crafted `traceparent` headers.

What to check

Upgrade `@opentelemetry/instrumentation-http` to 0.222.0, the affected OpenTelemetry-Go modules (`sdk`, `sdk/log`, `trace`, `baggage`, `propagation`) to 1.47.0, and Python `opentelemetry-api` to 1.45.2. Check stored server spans for exposed `url.query` secrets and rotate any leaked tokens.

A first fixed version is listed only when the advisory provides one. Advisory counts are not incident counts.
