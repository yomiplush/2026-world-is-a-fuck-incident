Gitea 28.4.0: 20 fixes including auto-init git hook overwrite RCE, owner password hash exposure, and authorization bypasses

The official Gitea 28.4.0 release disclosed 20 CVEs (18 included in this NVD publication window, 1 previously fixed in 28.3.0, and 1 Go 1.27.4 runtime update). Most notably, repository creation with auto-init accepted pushes before initialization completed, allowing a symlink README write to overwrite server-side git hooks and execute arbitrary commands as the Gitea system user (CVE-2026-125423), while dashboard search (`GET /repo/search`) in 28.0.0 and later returned repository owners' password hashes, salts, and email addresses inside commit status objects (CVE-2026-123006). Additional fixes cover git-quoted path bypass of protected file patterns to add workflows (CVE-2026-123638), persistent scoped workflow registrations after repository transfer exposing the previous owner's Actions secrets (CVE-2026-118535), unlimited TOTP verification attempts (CVE-2026-123002), continued OAuth2/OIDC refresh token use by disabled users (CVE-2026-128359), issue reference popup XSS (CVE-2026-120729), Git over HTTP pushes to repositories still being created (CVE-2026-129337), authorization boundary flaws across AGit PR creation, fork branch duplication, review replies, attachment deletion, container blob deletion, and LFS authentication (CVE-2026-123642, CVE-2026-123009, CVE-2026-126338, CVE-2026-123065, CVE-2026-129341, CVE-2026-120991, CVE-2026-120725, CVE-2026-125617, CVE-2026-127958, CVE-2026-128365, CVE-2026-129525), plus RubyGems registry newline injection fixed in 28.3.0 (CVE-2026-118389).

What to check

Update Gitea to 28.4.0 or later. If visible repositories with commit statuses were operated on 28.0.0 through 28.3.x, consider resetting owner account passwords, and audit scoped workflow registrations on transferred repositories as well as workflow history on protected branches.

A first fixed version is listed only when the advisory provides one. Advisory counts are not incident counts.
