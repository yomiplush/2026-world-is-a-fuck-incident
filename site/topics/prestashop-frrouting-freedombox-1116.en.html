PrestaShop, FRRouting, and FreedomBox: Revisions on multi-shop API boundary bypass, BGP attribute cache reuse, and SSH key path validation

From the NVD modification window, we supplement 3 previously disclosed issues whose technical conditions and fixed versions were refined. In PrestaShop prior to 8.2.9 and prior to 9.2.1, missing per-record shop ownership checks in `shopHasRight()` and `saveEntityFromXml()` allowed reading or modifying customer data (including password hashes and `secure_key`) across shops via the Webservice API (CVE-2026-71519), while passing `id_shop=all` or `id_shop_group=N` evaluated authorization as a logical OR across all shops without verifying the API key's permitted shop boundary (CVE-2026-71531); both are fixed in 8.2.9 and 9.2.1. For the FRRouting `bgpd` Tunnel Encapsulation attribute (type 23) use-after-free and double-free (CVE-2026-129456), the revised record specifies that when received from a peer configured with `soft-reconfiguration inbound`, the `attr_intern_reuse` cache compares the parsed attribute against itself, always matches, and reuses it without incrementing the sub-TLV reference count, adding fix commit `5c241056`. For FreedomBox prior to 26.15, references were updated for the flaw allowing unprivileged users to point their `authorized_keys` path to unauthorized files for read/write via a privileged helper (CVE-2026-123962, fixed in 26.15 and Debian LTS).

What to check

Update multi-shop PrestaShop deployments with Webservice API enabled to 8.2.9 or 9.2.1 or later and audit cross-shop customer record access by restricted API keys. In FRRouting, check for peers configured with `soft-reconfiguration inbound` and apply fixes including commit `5c241056`; update FreedomBox to 26.15 or distribution security updates.

A first fixed version is listed only when the advisory provides one. Advisory counts are not incident counts.
