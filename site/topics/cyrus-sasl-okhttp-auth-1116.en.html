Cyrus SASL and OkHttp: SRP public value A=N authentication bypass (plugin removed) and trailing-dot hostname certificate pin bypass

In Cyrus SASL 2.1.28 and earlier, the SRP server mechanism (`srp_server_mech_step2` in `plugins/srp.c`) fails to verify whether the client public value `A` is a multiple of the modulus `N` (`A % N == 0`). When an unauthenticated network client sends `A = N`, the shared secret is forced to zero, allowing authentication and session key establishment as any existing user without knowing the password (CVE-2026-129483, CVSS 4.0 9.3). Upstream has made no new release since 2022 and removed the SRP plugin entirely in commit `fb3724f4`. Separately, OkHttp 5.5.1 and earlier fails to normalize trailing-dot fully qualified domain names (e.g., `example.com.`) in `CertificatePinner` (`Pin.matchesHostname`), skipping pin checks when connecting with a trailing dot and allowing TLS interception with a certificate issued by any trusted CA (CVE-2026-129482, fixed in commit `30aa5897`; no fixed release version listed in NVD at capture time).

What to check

In environments using Cyrus SASL, disable the SRP mechanism or apply upstream commit `fb3724f4` (removing the SRP plugin) or distribution security packages. For applications using OkHttp `CertificatePinner`, normalize trailing dots on request hostnames or apply a build containing commit `30aa5897`.

A first fixed version is listed only when the advisory provides one. Advisory counts are not incident counts.
