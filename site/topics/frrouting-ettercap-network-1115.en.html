FRRouting bgpd and Ettercap: BGP attribute 23 double free / session drop and SOCKS5 / MOUNTD out-of-bounds reads

FRRouting `bgpd` logs but still processes Tunnel Encapsulation attributes (type 23) whose outer TLV length does not match the attribute length, allowing UPDATE messages from an established BGP neighbor to desynchronize reference counts on the interned sub-TLV chain (CVE-2026-129456). When routes are later replaced, withdrawn or cleared, `bgpd` writes to and double-frees freed memory, aborting `bgpd` and dropping all BGP sessions on the router (RFC 9012 requires filtering it on eBGP by default, but `bgpd` processes it unless explicitly discarded). Separately, Ettercap through 0.8.5.1 has heap out-of-bounds reads in `dissector_socks()` via unchecked SOCKS5 username/password lengths (CVE-2026-129431) and in `dissector_mountd()` via independent RPC credential/directory length checks (CVE-2026-129432), leaking heap memory to console and logs.

What to check

Verify that the FRRouting fix commits (`abef07b5` / `bebf95f0`, PR #21176) are applied and filter BGP attribute 23 (Tunnel Encapsulation) on untrusted eBGP sessions. For Ettercap (through 0.8.5.1), no fixed release version is listed in NVD at retrieval time (PR #1340 and #1341); avoid running SOCKS5 and mountd dissectors on untrusted network segments.

A first fixed version is listed only when the advisory provides one. Advisory counts are not incident counts.
