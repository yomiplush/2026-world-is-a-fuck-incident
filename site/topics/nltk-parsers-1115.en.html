NLTK: 3 quadratic-time CPU exhaustion advisories in CCG, Chomsky Normal Form and CoNLL SRL parsers, plus 2 withdrawn duplicate updates

As the 3 GHSA reviewed advisories in the publication window, 3 quadratic-time (O(n^2)) CPU exhaustion issues caused by pure-Python loops in NLTK 3.10.3 and below were published: tail re-slicing on bracket bodies and operator chains in `nltk.ccg.lexicon.fromstring` (and `nltk.ccg.chart.fromstring`, CVE-2026-126299 / GHSA-89p3-fcch-88ph), repeated `list.pop(0)` calls in the default right-factor branch of `Tree.chomsky_normal_form()` (CVE-2026-126298 / GHSA-r53h-rw34-8h97), and nested predicate/span-column rescanning in `ConllCorpusReader.srl_instances()` (CVE-2026-126297 / GHSA-v8f3-6phw-6mh9). Neither the recursion-depth guard (`MAX_PARSE_DEPTH`) nor the regex timeout wraps these loops, allowing a few megabytes of untrusted input to pin a worker CPU core for tens of seconds. The 5 GHSA reviewed records in the modification window consist of these 3 canonical advisories and 2 duplicate advisories withdrawn with `withdrawn_at` (GHSA-6665-2vj3-h76r and GHSA-qvhx-rvgc-jhwf).

What to check

Upgrade NLTK to fixed version 3.10.4 or later. Services that parse untrusted CCG lexicons, Treebank trees or CoNLL SRL corpora should also enforce input size caps and worker execution budgets.

A first fixed version is listed only when the advisory provides one. Advisory counts are not incident counts.
