NLTK: 5 canonical advisories for C-extension path bypass, corpus symlinks and parser CPU exhaustion

5 canonical advisories fixed in NLTK 3.10.4: `BllipParser` passes caller-supplied model paths to the native `bllipparser` C extension without `pathsec` validation, enabling arbitrary file read (CVE-2026-126295); `YCOECorpusReader` performs only lexical path checks on `psd`/`pos` directories and follows symlinks outside the corpus root (CVE-2026-126304); and unbounded or quadratic CPU consumption affects `SteppingRecursiveDescentParser.parse()` (CVE-2026-126303), `TreebankWordTokenizer.span_tokenize` (CVE-2026-126300), and `LegalitySyllableTokenizer.tokenize` (GHSA-gpwc-27cw-rh9r).

What to check

Upgrade `nltk` to 3.10.4. Audit code paths that pass untrusted model paths, corpus archives, grammars or long tokens to these parsers and tokenizers.

A first fixed version is listed only when the advisory provides one. Advisory counts are not incident counts.
