Vim, GPAC/MP4Box, libdca and sox_ng: PowerShell help lookup quote bypass and media parser boundaries

In Vim before 9.2.1346, the PowerShell filetype plugin (`runtime/ftplugin/ps1.vim`) doubled only ASCII single quotes `'` in its fix for GHSA-r5v6-q6j8-8qw2, leaving typographic quotes treated as single quotes by PowerShell (U+2018, U+2019, U+201A and U+201B) unescaped and allowing arbitrary command execution when a user selects a crafted line in Visual mode and presses `K` (no CVE assigned yet). In media parsers, 2 type confusions and 1 use-after-free during XMT scene loading in GPAC/MP4Box through 26.07.0 (CVE-2026-124030, CVE-2026-124031 and CVE-2026-128240; fixed in commits `1359c4da`, `43a8329a` and `a2e5c62c`, no release version number listed), an out-of-bounds table read in differential scale-factor parsing in unmaintained VideoLAN `libdca` (HEAD `95c4bd8`, CVE pending, no upstream fix), and an out-of-bounds write in the VOC decoder `read_samples_voc` in `sox_ng` through 14.8.1 (CVE-2026-129264, patch `0b40408b`) were disclosed.

What to check

Upgrade Vim to 9.2.1346 or later, and avoid pressing `K` on Visual selections in untrusted PowerShell scripts on unpatched installations. Update GPAC and `sox_ng` to builds containing the fix commits, and check distribution patches or migrate off unmaintained `libdca` (as done in VLC 4.0).

A first fixed version is listed only when the advisory provides one. Advisory counts are not incident counts.
