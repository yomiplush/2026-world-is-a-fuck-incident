Perl JSON::XS (7 CVEs), HTTP::Session and Dancer: Incremental parser buffer corruption and session ID injection

7 advisories in Perl JSON::XS before 4.05 and 2 unvalidated session ID advisories in HTTP::Session and Dancer were published in NVD and oss-security. In JSON::XS, appending a 1-byte chunk in `incr_parse` writes 1 byte past a heap buffer (CVE-2026-129114, 3.04 before 4.05), `incr_skip` after a top-level number wraps the buffer length (CVE-2026-129113, 4.0_00 before 4.05), input after a NUL byte buffers past `max_size` (CVE-2026-124536, before 4.05), `FREEZE` stack reallocation under `allow_tags` reads freed stack memory (CVE-2026-129115, 3.0 before 4.05), nested tagged values exhaust the C stack (CVE-2026-124540, before 4.05), and rejected JSON inputs leak memory in 2 paths (CVE-2026-124539 and CVE-2026-124541, before 4.05). In addition, HTTP::Session before 0.43 allows CRLF memcached command injection via cookie session IDs in `HTTP::Session::Store::Memcached` (CVE-2011-10042, distribution deprecated in 0.54), and Dancer before 1.3400 passes unvalidated cookie session IDs from `read_session_id` to session engines (CVE-2015-10149).

What to check

Upgrade JSON::XS to 4.05 or later and Dancer to 1.3400 or later. Although HTTP::Session 0.43 fixed the memcached injection, the distribution was marked deprecated in 0.54; migrate to an alternative such as `Plack::Middleware::Session`.

A first fixed version is listed only when the advisory provides one. Advisory counts are not incident counts.
