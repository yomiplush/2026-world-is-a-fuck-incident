Dokploy and Pulse: Root command injection via Compose backup serviceName and missing authorization on AI approval APIs

In Dokploy before 0.31.1, `getComposeContainerCommand()` uses the `serviceName` parameter saved by authenticated organization members via `backup.create` or `backup.update` tRPC procedures without shell metacharacter validation, executing arbitrary commands as root when scheduled backups run and enabling host takeover via the mounted Docker socket (CVE-2026-129433, CVSS 9.9). In Pulse from 5.0.17 before 6.8.0, the `/api/ai/approvals` endpoints lack authorization checks, allowing authenticated viewer-level users to list pending requests and approve or deny other users' requests (CVE-2026-129428).

What to check

Upgrade Dokploy to 0.31.1 or later and Pulse to 6.8.0 or later. Audit existing Dokploy backup configurations for suspicious `serviceName` values and review Pulse AI approval history for unauthorized approvals.
