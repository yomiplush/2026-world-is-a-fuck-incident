Assimp, GPAC, littlefs, MicroQuickJS, and Escargot: 11 memory safety flaws across 3D model, media, embedded FS, and JS engines

In the 3D model import library Assimp 6.0.6 and earlier, 4 vulnerabilities were published (all with upstream PRs referenced and no fixed release version listed in NVD at capture time): local file read via glTF/glTF2 `buffers[].uri` path traversal (CVE-2026-129477, PR #7027), heap out-of-bounds read on data URIs exceeding 127 bytes due to a `signed char` offset in `glTFCommon::Util::ParseDataURI` (CVE-2026-129478, PR #7029), 32bit size calculation integer overflow in `OgreBinarySerializer::ReadSubMesh` (CVE-2026-129479, PR #7026), and heap out-of-bounds read from unvalidated `frameSize` in `MD2Importer::InternReadFile` (CVE-2026-129480, PR #7028). We also cataloged 4 NULL pointer dereference and type confusion flaws in MPEG-2 TS, XMT, and DASH handling in GPAC prior to 26.02.0 (CVE-2025-71466, CVE-2025-71467, CVE-2025-71468, CVE-2025-71469, fixed in 26.02.0 and commit `62714f27`), stack out-of-bounds read via `lfs_dir_traverse()` type confusion when `LFS_MIGRATE` is enabled in littlefs 2.11.3 and earlier (CVE-2026-129490, no fixed version listed), stale frame pointer traversal upon exception in `JS_Call()` in MicroQuickJS (`mquickjs`) (CVE-2025-71470, fixed in commit `99eed3f9`), and a modified-window `ReloadableString` / `CompressibleString` use-after-free in Samsung Escargot 5.0.2 (CVE-2026-124684, fixed in commit `8bc35b7b`).

What to check

Update GPAC to 26.02.0 or later (including later commits for the separate 26.07.0 and earlier issues noted previously), and apply the fix commits for MicroQuickJS (`99eed3f9`) and Escargot (`8bc35b7b`). For Assimp 6.0.6 and earlier, apply upstream PRs (#7026 to #7029) or restrict untrusted glTF/MD2/Ogre mesh inputs, and disable `LFS_MIGRATE` on untrusted v1 images in littlefs.

A first fixed version is listed only when the advisory provides one. Advisory counts are not incident counts.
