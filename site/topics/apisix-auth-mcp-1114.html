Apache APISIX：認証header残留・経路正規化差・openapi-to-mcp境界の7件

Apache APISIX 3.20.0で修正された7件。multi-authのwolf-rbac fallback時（CVE-2026-124666、3.8.0〜3.19.0）やjwe-decryptの `strict: false`・forward-authの `allow_degradation: true`（CVE-2026-124679、3.18.0〜3.19.0）でclient提供の身分headerが上流へ残る。またencoded dot segmentの解釈差によるroute認証迂回（CVE-2026-124680、0.9〜3.19.0）、authz-keycloakの単一scope一致によるmethod突破（CVE-2026-124716、1.4.0〜3.19.0）、`match_uri_encoded_slash` と `skip_mtls_uri_regex` 併用時のmTLS迂回（CVE-2026-124723、3.18.0〜3.19.0）、openapi-to-mcpでの身分なりすましと未宣言API path到達（CVE-2026-124719・CVE-2026-124726、3.19.0）が公表された。

確認すること

Apache APISIXを3.20.0へ更新する。gatewayのplugin設定（`strict: false`、`allow_degradation: true`、`match_uri_encoded_slash`、openapi-to-mcp等）と、上流service側がclient提供の身分headerをそのまま信頼していないかを点検する。

修正版は勧告の記載がある場合だけ示します。勧告数は被害件数ではありません。
