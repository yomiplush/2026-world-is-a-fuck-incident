Unauthenticated JWT Secret Disclosure via /skServer/ziplogs Leads to Full Admin Account Takeover
Critical
tkurki
published
GHSA-4w32-qx5g-cpwv
Sep 21, 2026
Package
npm
signalk-server
(
npm
)
Affected versions
< 2.32.0
Patched versions
>=2.33.0
Description
Summary
/skServer/ziplogs
is accessible without authentication and returns a ZIP archive that includes
security.json
. That file contains the server's HS256 JWT signing key (
secretKey
). An attacker who retrieves this key can forge a valid admin JWT, create a persistent admin account, and log in with real credentials.
As of the date checked through Shodan, around 66 servers are potentially affected globally.
Details
Missing authentication on
/skServer/ziplogs
.The route streams the config/log directory as a ZIP to any caller. Admin middleware protects
/skServer/logfiles/
but not
ziplogs
.
secretKey
included in the archive
.The bundle includes
security.json
(e.g.
sk-logs--<timestamp>/security.json
) with the symmetric HS256 signing key used to issue and verify JWTs.

Impact
Full unauthenticated admin takeover. An attacker can create a persistent admin account and then authenticate via the normal login flow (no forged JWT required after account creation).
On vessels, admin access to Signal K implies control over NMEA routing, plugin configuration, and alarms. Many instances are exposed on the default port and discoverable via internet scanners.
Recommendation
Guard
/skServer/ziplogs
with the same admin middleware as other
/skServer/*
routes (unauthenticated requests should return 401).
Maybe exclude
security.json
from downloadable archives regardless of auth.
