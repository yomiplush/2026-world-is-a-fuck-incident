L134: ## Axivion
L135: ### CVE-2026-86350
L136: 
L137: Because our Dashboard redistributes Apache Tomcat, we inherit CVE-2026-86350 (fixed in 11.0.26) and its criticality, since we can't rule out that the Dashboard is affected.
L138: 
L139: Impact: Remote Privilege Escalation. A completely unauthorized user could become able to execute requests on behalf of a Dashboard Administrator.
L140: 
L141: Affected versions: Axivion Dashboard: from 7.12.1 to 7.12.5 and from 7.11.7 to 7.11.8
L142: 
L143: Fixed: Axivion 7.11.9, 7.12.6 and 7.13.0 or later
L144: ### CVE-2026-12593
L145: 
L146: CWE-862 Missing Authorization vulnerability in the Dashboard OAuth/OIDC implementation
L147: 
L148: Impact: Authenticated Remote Privilege escalation. Any OIDC/OAuth authenticated user can become a Dashboard Administrator. By exploiting another weakness this can also lead to arbitrary code execution on the host-system running the Dashboard in the context of the OS-User used to run the Dashboard.
L149: Affected versions: From Axivion 7.8.5 to 7.8.12, from 7.9.0 to 7.9.12, from 7.10.0 to 7.10.10, from 7.11.0 to 7.11.6, from 7.12.0 to 7.12.1
L150: 
L151: Fixed: Axivion 7.9.13 and 7.10.11, 7.11.7, 7.12.2 or later
L152: ### CVE-2026-12379
L153: 
L154: CWE-601 URL Redirection to Untrusted Site ('Open Redirect') vulnerability in the Dashboard OAuth/OIDC implementation
L155: Impact: Redirection of unsuspecting users to an untrusted external site. The Dashboard's OAuth/OIDC login flow did not properly restrict the post-authentication redirect to the application's own origin, so a user who follows a crafted login link can be sent to an attacker-controlled site after authenticating against the genuine Dashboard. Because the link points at the legitimate Dashboard, this can be abused for phishing, e.g. credential or second-factor theft via a convincing look-alike page.
L156: Affected versions: From Axivion 7.8.0 to 7.8.12, from 7.9.0 to 7.9.12, from 7.10.0 to 7.10.10, from 7.11.0 to 7.11.6, from 7.12.0 to 7.12.1
L157: 
L158: Fixed: Axivion 7.9.13 and 7.10.11, 7.11.7, 7.12.2 or later
L159: ## Qt Framework
L160: ### CVE-2026-105946:
L161: 
L162: Out-of-bounds read vulnerability in NTLM authentication handling impacts Qt
L163: 
L164: Impact: A malicious server or proxy that requests NTLM authentication can cause the application to read outside the bounds of an allocated buffer. This may disclose application heap memory contents to the remote party and may cause the application to terminate.
L165: 
L166: Affected versions: From Qt 6.8.0 to Qt 6.8.9, from Qt 6.9.0 to Qt 6.11.1. Affected status unknown before Qt 6.8.0
L167: Fixed: Qt 6.11.2, Qt 6.8.10, Qt 6.12.0
L168: ### CVE-2026-107590:
L169: 
L170: Out-of-bounds write vulnerability in QTextCodec iconv-based encoding impacts Qt
L171: 
L172: Impact: Under certain conditions, encoding text with QTextCodec may write outside an internal buffer. This can cause the application to crash and may affect data integrity.
L173: 
L174: Affected versions: from Qt 4.5.0 to Qt 6.8.8, from Qt 6.9.0 to Qt 6.11.2
L175: 
L176: Fixed: Qt 6.8.9, Qt 6.11.3, Qt 6.12.0

L0: # CVE-2026-117468: Device-code claim permits restricted token escalation in Psono Server
L1: 
L2: * **Publication date:** 2026-10-27
L3: * **Last updated:** 2026-10-27
L4: * **CVE ID:** CVE-2026-117468
L5: * **Affected product:** Psono
L6: * **Affected modules:** Psono Server Community Edition and Psono Server Enterprise Edition
L7: * **Affected versions:** 5.3.5 through 7.2.3
L8: * **Fixed version:** 7.2.4
L9: * **Severity:** Medium
L10: ## Summary
L11: 
L12: Psono Server used a permission class that did not enforce token write scope when claiming a device code. An authenticated attacker holding a restricted API key-derived session could claim an attacker-controlled device code and obtain a full read-write session valid for up to 365 days.
L13: 
L14: The issue affected both Psono Server Community Edition and Psono Server Enterprise Edition. It did not bypass two-factor authentication or directly disclose plaintext secrets.
L15: ## Impact
L16: 
L17: The vulnerability bypassed the original API key session's scope and lifetime restrictions. A successful attacker could retain long-term account access and modify encrypted secrets and shares despite starting with a read-only, short-lived session.
L18: 
L19: * **CVSS v3.1 base score:** 6.5 (Medium)
L20: * **CVSS vector:** `CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:U/C:N/I:H/A:N`
L21: * **Weakness:** CWE-269, Improper Privilege Management
L22: ## Remediation
L23: 
L24: Upgrade Psono Server Community Edition and Psono Server Enterprise Edition to version 7.2.4 or later.
L25: 
L26: ## Workaround
L27: 
L28: If an immediate upgrade is not possible, block device-code claim requests at the reverse proxy or disable device pairing until the upgrade can be applied. Blocking this endpoint prevents legitimate device pairing.
L29: ## Timeline
L30: 
L31: * **2026-07-29 18:10 GMT+2:** Vulnerability reported to esaqa GmbH.
L32: * **2026-07-30 09:13 GMT+2:** Vendor fix implemented.
L33: * **2026-07-30 15:16 GMT+2:** Psono 7.2.4 released with the fix.
L34: 
L35: ## Acknowledgements
L36: 
L37: This vulnerability was reported by Ryan Chaplin.
