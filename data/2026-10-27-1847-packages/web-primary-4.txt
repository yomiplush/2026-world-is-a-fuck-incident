L137: Because our Dashboard redistributes Apache Tomcat, we inherit CVE-2026-86350 (fixed in 11.0.26) and its criticality, since we can't rule out that the Dashboard is affected.

L139: Impact: Remote Privilege Escalation. A completely unauthorized user could become able to execute requests on behalf of a Dashboard Administrator.

L144: ### CVE-2026-12593
L145: 
L146: CWE-862 Missing Authorization vulnerability in the Dashboard OAuth/OIDC implementation
L147: 
L148: Impact: Authenticated Remote Privilege escalation. Any OIDC/OAuth authenticated user can become a Dashboard Administrator. By exploiting another weakness this can also lead to arbitrary code execution on the host-system running the Dashboard in the context of the OS-User used to run the Dashboard.
L149: Affected versions: From Axivion 7.8.5 to 7.8.12, from 7.9.0 to 7.9.12, from 7.10.0 to 7.10.10, from 7.11.0 to 7.11.6, from 7.12.0 to 7.12.1

L152: ### CVE-2026-12379
L153: 
L154: CWE-601 URL Redirection to Untrusted Site ('Open Redirect') vulnerability in the Dashboard OAuth/OIDC implementation
L155: Impact: Redirection of unsuspecting users to an untrusted external site. The Dashboard's OAuth/OIDC login flow did not properly restrict the post-authentication redirect to the application's own origin, so a user who follows a crafted login link can be sent to an attacker-controlled site after authenticating against the genuine Dashboard. Because the link points at the legitimate Dashboard, this can be abused for phishing, e.g. credential or second-factor theft via a convincing look-alike page.
L156: Affected versions: From Axivion 7.8.0 to 7.8.12, from 7.9.0 to 7.9.12, from 7.10.0 to 7.10.10, from 7.11.0 to 7.11.6, from 7.12.0 to 7.12.1

L0: # CVE-2026-117469: File-transfer type confusion permits unauthorized repository writes in Psono Server
L1: 
L2: * **Publication date:** 2026-10-27
L3: * **Last updated:** 2026-10-27
L4: * **CVE ID:** CVE-2026-117469
L5: * **Affected product:** Psono
L6: * **Affected modules:** Psono Server Community Edition and Psono Server Enterprise Edition
L7: * **Affected versions:** 1.0.0 through 7.2.3
L8: * **Fixed version:** 7.2.4
L9: * **Severity:** Medium
L10: ## Summary
L11: 
L12: Psono Server did not enforce the direction of file-transfer credentials on file-repository operations. An authenticated attacker with read-only access to a file could present a download transfer to the upload endpoint and perform repository writes.
L13: 
L14: The issue affected both Psono Server Community Edition and Psono Server Enterprise Edition where external file repositories were used.
L15: ## Impact
L16: 
L17: A successful attacker could obtain a signed upload URL for an attacker-selected object key and append a chunk to the file owner's external repository. This could upload or overwrite repository objects, consume storage, and disrupt stored files. The impact was bounded by the transfer's size, chunk-count, and 12-hour lifetime limits, but fresh download transfers made the attack repeatable.
L18: * **CVSS v3.1 base score:** 5.4 (Medium)
L19: * **CVSS vector:** `CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:U/C:N/I:L/A:L`
L20: * **Weakness:** CWE-862, Missing Authorization
L21: ## Remediation
L22: 
L23: Upgrade Psono Server Community Edition and Psono Server Enterprise Edition to version 7.2.4 or later.
L24: 
L25: ## Workaround
L26: 
L27: If an immediate upgrade is not possible, disable external file repositories or block the file-repository upload endpoint until the upgrade can be applied. Blocking the endpoint prevents legitimate repository uploads.

L1: 
L2: * **Publication date:** 2026-10-27
L3: * **Last updated:** 2026-10-27
L4: * **CVE ID:** CVE-2026-117470
L5: * **Affected product:** Psono
L6: * **Affected modules:** Psono Server Community Edition and Psono Server Enterprise Edition
L7: * **Affected versions:** 3.1.0 through 7.2.3
L8: * **Fixed version:** 7.2.4
L9: * **Severity:** Medium
L10: ## Summary
L11: 
L12: Psono Server did not consume a stored WebAuthn challenge after assertion verification. An attacker who possessed a user's password and one captured valid WebAuthn assertion could replay that assertion with separate login tokens while the challenge remained unchanged.
L13: 
L14: The issue affected both Psono Server Community Edition and Psono Server Enterprise Edition where WebAuthn two-factor authentication was enabled.
L15: ## Impact
L16: 
L17: Successful exploitation bypassed the WebAuthn second factor and granted account access. Capturing a valid assertion required a compromised or malicious client, browser extension, or server-side request logging. The vulnerability did not itself disclose plaintext secrets.
L18: 
L19: * **CVSS v3.1 base score:** 6.5 (Medium)
L20: * **CVSS vector:** `CVSS:3.1/AV:N/AC:H/PR:N/UI:N/S:U/C:L/I:H/A:N`
L21: * **Weakness:** CWE-294, Authentication Bypass by Capture-replay
L22: ## Remediation
L23: 
L24: Upgrade Psono Server Community Edition and Psono Server Enterprise Edition to version 7.2.4 or later.
L25: 
L26: ## Workaround
L27: 
L28: No complete server-side workaround is available. If an immediate upgrade is not possible, disable WebAuthn and require another supported second factor until the upgrade can be applied.

L0: # CVE-2026-117471: User-controlled Duo host permits authenticated SSRF in Psono Server
L1: 
L2: * **Publication date:** 2026-10-27
L3: * **Last updated:** 2026-10-27
L4: * **CVE ID:** CVE-2026-117471
L5: * **Affected product:** Psono
L6: * **Affected modules:** Psono Server Community Edition and Psono Server Enterprise Edition
L7: * **Affected versions:** 0.1.0 through 7.2.3
L8: * **Fixed version:** 7.2.4
L9: * **Severity:** Medium
L10: ## Summary
L11: 
L12: Psono Server accepted a user-controlled host when configuring a personal Duo device and passed it to the Duo client without a host allowlist or explicit timeout. An authenticated attacker could induce outbound HTTPS connections to selected hosts.
L13: 
L14: The issue affected both Psono Server Community Edition and Psono Server Enterprise Edition where personal Duo configuration was available.
L15: ## Impact
L16: 
L17: Differences in DNS, connection, TLS, and Duo API failures provided an internal DNS and port-443 service-reachability oracle. Unresponsive targets could also occupy a server worker until the operating-system timeout. The Duo client required HTTPS on port 443 and validated TLS certificates, so the vulnerability did not provide arbitrary protocol or port access and could not reach plain-HTTP cloud metadata services.
L18: * **CVSS v3.1 base score:** 5.4 (Medium)
L19: * **CVSS vector:** `CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:U/C:L/I:N/A:L`
L20: * **Weakness:** CWE-918, Server-Side Request Forgery (SSRF)
L21: ## Remediation
L22: 
L23: Upgrade Psono Server Community Edition and Psono Server Enterprise Edition to version 7.2.4 or later.
L24: 
L25: ## Workaround
L26: 
L27: If an immediate upgrade is not possible, prevent users from configuring personal Duo hosts and restrict server egress on port 443 to approved Duo domains. System-wide Duo configuration with an administrator-controlled host is not affected by the user-controlled-host path.

L0: # CVE-2026-117472: URL prefix handling permits API key read-scope bypass in Psono Server
L1: 
L2: * **Publication date:** 2026-10-27
L3: * **Last updated:** 2026-10-27
L4: * **CVE ID:** CVE-2026-117472
L5: * **Affected product:** Psono
L6: * **Affected modules:** Psono Server Community Edition and Psono Server Enterprise Edition
L7: * **Affected versions:** 4.0.33 through 7.2.3
L8: * **Fixed version:** 7.2.4
L9: * **Severity:** Medium
L10: ## Summary
L11: 
L12: Psono Server compared the bulk-secret-read request path with a hard-coded unprefixed path. In deployments configured with `URL_PREFIX`, this comparison failed and the POST request was authorized using write scope instead of read scope.
L13: 
L14: The issue affected both Psono Server Community Edition and Psono Server Enterprise Edition. Deployments without `URL_PREFIX` were not affected.
L15: ## Impact
L16: 
L17: An authenticated attacker with a read-disabled, write-enabled API key could retrieve encrypted secret data and nonces through the prefixed bulk-secret-read endpoint despite lacking read permission. Write-only API keys are supported but unusual, and the vulnerability did not disclose plaintext secret contents.
L18: 
L19: * **CVSS v3.1 base score:** 4.3 (Medium)
L20: * **CVSS vector:** `CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:U/C:L/I:N/A:N`
L21: * **Weakness:** CWE-863, Incorrect Authorization
L22: ## Remediation
L23: 
L24: Upgrade Psono Server Community Edition and Psono Server Enterprise Edition to version 7.2.4 or later.
L25: 
L26: ## Workaround
L27: 
L28: If an immediate upgrade is not possible, remove the `URL_PREFIX` configuration or avoid issuing API keys with read disabled and write enabled until the upgrade can be applied.
L29:
