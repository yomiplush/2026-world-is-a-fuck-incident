## kaniko: Azure build tokens sent to lookalike registries

Untrusted Dockerfiles or build arguments can expose ARM access tokens when the build can obtain an Azure identity. Neither RUN nor push is required; using ACR is not a prerequisite. The fix is 1.25.20, but this repository publishes no binaries or images. The original acr-env module has no fixed release.

Rebuild the executor, warmer and credential helper from 1.25.20 or later. Review Entra and Azure logs and identity permissions for suspect builds. Rotating credentials does not revoke issued tokens; investigate their remaining lifetime and any secrets the identity could read.

## LXD: restored snapshots bypass restricted-project controls

The advisory reports that imported snapshots bypass lowlevel-hook restrictions and can execute commands with host privileges. Transfer and restore capabilities are prerequisites; this does not establish unauthenticated RCE on every public API. The narrative cites Incus while the table describes LXD Go module boundaries.

Audit snapshot import, transfer and restore permissions and update the applicable vendor release line. Do not mechanically convert Go pseudo-versions into LXD distribution or Incus release numbers.

## LXD: source authorization and DevLXD volume ownership

Cross-project instance and custom-volume copies check the destination without establishing permission to view the source. A separate DevLXD issue allows a guest with volume management enabled to read and write another guest’s volumes within the same project. These are different authorization boundaries.

Review copy permissions, source-project visibility and DevLXD volume-management settings. Restrict unnecessary guest permissions and investigate unexpected copies, device changes and secret access. Keep each advisory’s module boundary rather than reducing them to one release number.

## listmonk: export omits the query route’s table authorization

The export SQL injection requires an authenticated user with subscribers:sql_query and subscribers:get_all. Missing table checks can expose password hashes and SMTP credentials. The advisory also describes modifying CTEs outside a read-only transaction. This is not an unauthenticated public SQL injection.

Restrict the affected permissions and deploy a build containing the official fix. Do not equate the table’s Go pseudo-version with a product release number. Investigate exports, database changes and credential access.

## OSAC: kubeconfig exec plugins run inside the proxy pod

In remote or auto VM cluster mode, the attacker must be able to create or modify a labelled Secret in a namespace readable by the proxy. Its exec plugin runs with console-proxy pod privileges; the server URL is also an SSRF path. Local-only deployments are unaffected. The advisory names 0.0.4 while asking users to verify a release containing the patch.

Restrict Secret writes in the relevant namespace and verify that the deployed image contains the fix. Pod execution does not establish host root; investigate service-account permissions, destinations and Secret changes.

## hawkBit: authenticated devices retrieve unassigned firmware within a tenant

DDI versions 1.0.3 and earlier allow an authenticated device to retrieve unassigned firmware artifacts within the same tenant. This does not establish authentication bypass or cross-tenant access. Metadata listing assists discovery. The API names 1.0.4 as fixed.

Update to the applicable fix in 1.0.4 or later and review device credentials, downloads and tenant assignments. Keep secrets out of firmware and investigate access to distributed artifacts.

## filecoin-pin: DAG pinning lacks resource bounds

Versions through 1.1.0 retrieve caller-selected DAGs without bounds, consuming disk, network, CPU and other resources. Authentication is normally required; ALLOW_NO_AUTH=true also exposes an unauthenticated path. The API names 1.1.1 as fixed.

Apply the fix in 1.1.1 or later and verify pin-request, disk, concurrency and timeout limits and monitoring. Check authentication on public deployments; a syntactically valid CID alone does not make a pin safe.

## Banks: Tool.import_path bypasses the template sandbox boundary

An attacker-influenced prompt body can define Tool JSON; a matching LLM tool call then invokes an arbitrary Python callable in the hosting process. This differs from the Jinja sandbox fix in 2.4.2. API metadata lists versions through 2.4.2 as affected and 2.4.3 as fixed. Distinguish the earlier narrative from current package metadata.

Update to 2.4.3 or later and verify resolution against a startup-registered tool allowlist. Restrict prompt-registry and shared-file writes; the Jinja sandbox alone does not address this path.
