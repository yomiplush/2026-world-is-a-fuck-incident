## Priorities

- **Confirmed exploitation:** Arista VCO and Nextcloud Built-in CODE joined KEV on October 23 (federal due date October 26, forensic triage required). VCO needs a valid low-privilege session; CODE permits unauthenticated execution while the CODE process is stopped. Disabling the Nextcloud app is insufficient: update to 26.4.303 or remove it.
- **Untrusted input:** review Pillow FPX (optional olefile dependency), Wasmtime Cranelift, Ruby regexp compilation and Perl's bundled Brotli. Update the component that actually contains the vulnerable code.
- **Access boundaries:** Laravel TokenGuard, Echo proxy, PraisonAI AgentOS, ReqLLM WebSockets and obsidian-tc vault isolation have different configuration requirements. The register records those separately.
- **Infrastructure:** HPE's official CSAF has 72 vulnerabilities, including eight at CVSS 10.0, with fixes in 10.8.1.2 / 10.7.2.7 / 10.4.1.14 / 8.13.3.1 / 8.10.0.24. Match each CVE to the applicable product line. A maximum score is not evidence of exploitation.
- **Japan:** Pleasanter LDAP authentication bypass (fix 1.5.9.1), LIFF SDK XSS (2.31.1), Mitsubishi industrial products, Lenovo AVB test keys, and JPCERT's updated domestic Web/API intrusion warning are covered.
- **Trust and incidents:** Mozilla embeds the eMudhra intermediate block list; BlackX illustrates why Secure Boot revocation state matters. The k0t report's 70,000+ figure counts credentials and related data, not affected companies.

## Important limits

Pillow's published FPX demonstration uses a pinned setup with ASLR disabled; it is not an observed fleet-wide attack rate. Wasmtime CVE-2026-115889 was checked against the maintainer advisory; the separate -115893 record detected in NVD was not conflated with it. Ruby's timeout does not prevent these compilation bugs; 4.0.8 lacks the complete fix. NGINX exposure depends on directives and some execution paths also require ASLR bypass/disablement. Exact minimum x402 package versions still need release-level confirmation. BlackX follows administrator access; it is not a new unauthenticated initial-entry bug.

PHP's latest informational advisory and emergency release lines were unchanged in this collection. Keep the session upload progress mitigation described in [docs/23](23-php-cve-2026-115560.md). The former inability to retrieve Arista's primary advisory is resolved; its two observed attack IPs are recorded in the research note.
