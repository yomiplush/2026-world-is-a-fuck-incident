# 証拠資料のキー伏せ処理

2026年10月30日、保存HTML（gzipを含む）4ファイル内の外部サイト由来のGoogle APIキーを `[REDACTED_GOOGLE_API_KEY]` に置換しました。指摘されたImpervaの資料では、取得元サイトの `GOOGLE_GEOCODE_CLIENT_API_KEY` 設定が保存されていました。これだけでInfosec Briefingの侵害や、キーの所有者・有効性・制限設定が確認されたわけではありません。キーの使用・有効性テストは実施していません。

[処理記録](../data/evidence-redactions.json)に、対象パス、処理前後の保存バイト列のSHA-256、更新した整合性マニフェストを記載しました。更新後のハッシュは**キーを伏せた資料**のもので、取得時の原本そのものではありません。取得時のヘッダーは過去のメタデータとして残しています。記事内容と調査記録は保持し、gzipは決定的に再圧縮しました。原本保存方針に対する例外として処理を記録しています。

証拠資料の公開前に `python3 tools/intel/check-saved-secrets.py` を実行してください。追跡ファイルとgzip展開後の本文にあるGoogle APIキー形式を検査し、キー値は出力しません。全種類の秘密情報を検出するものではなく、Git履歴は検査しません。

現在のコピーを削除してもキーは失効せず、過去のGitコミット・既存のクローン・フォーク・GitHubのキャッシュからも消えません。所有者側で制限設定を確認し、必要に応じてキーを無効化・再発行する必要があります。Git履歴の削除、調整を伴う強制Push、GitHubの秘密情報アラートの解決は別の作業です。今回の処理で履歴の書き換えやキーの無効化は実施していません。
