# Apache、2026年10月 — 3プロジェクト、深刻度ラベルについての1つの教訓

[English](15-apache-oct2026.md) | [**日本語**](15-apache-oct2026.ja.md)

Apache の10月分は、このリポジトリの他の事案と対になる好例です。CVE は実在し、いくつかは深刻で、
そして**CISA KEV には1件も入っていません**。さらに、ベンダの深刻度ラベルと CVSS が最もはっきり
食い違うのも、同じ製品ファミリの中でした。

以下の数値は各プロジェクトの公式セキュリティページ（`tomcat.apache.org`、`httpd.apache.org`）と、
`security@apache.org` が登録した NVD レコードに基づきます。OpenCVE のベンダ一覧は候補の探索に
だけ使い、**総数 3,832 件**と表示されることは、絞り込みなしのフィードが出発点にならない証拠です。

## 1. Tomcat — 同じ日に3件の "Important"、3ブランチ修正

公開 **2026-10-20**、修正 **11.0.27 / 10.1.61 / 9.0.123**。

| CVE | Apache のラベル | CVSS | 内容 | 影響（11.0系） |
|---|---|---|---|--|
| `CVE-2026-101296` | **Important** | 4.0 **9.1** | JNDIRealm が非 GSSAPI SASL で**フェイルオープン**。正しいパスワード無しで認証できてしまう | 11.0.0-M1 → 11.0.26 |
| `CVE-2026-101356` | **Important** | 3.1 **9.1** | HTTP/2 非同期サーブレットのオブジェクト再利用誤り → **利用者間で**リクエスト/レスポンスが混線 | 11.0.22 → 11.0.26 |
| `CVE-2026-103119` | **Important** | — | **AJP** の応答混線。バッファ下読みで応答本文が2つのリクエストに分割され、前の応答が次へ漏れる | 11.0.0-M25 → 11.0.26 |
| `CVE-2026-93446` | Low | — | TLS 1.3 接続が断続的に失敗 | 11.0.0-M21 → 11.0.26 |
| `CVE-2026-88041` | Low | — | HTTP/2 のトレーラ情報が次のリクエストへ漏れる | — |
| `CVE-2026-74049` | Low | — | Jasper JSTL の `<c:redirect>` がページ処理を止めない | — |
| `CVE-2026-74048` | Low | — | FIPS 有効化失敗時に非 FIPS の JSSE へフォールバック | — |

上の3件をまとめて読んでください。**仕組みは違うが結末は同じ**——「ある利用者のリクエストや
レスポンスが、別の利用者へ渡る」。マルチテナントのアプリにとって最悪の故障形態で、ここの
"Important" が「中くらい」ではない理由です。`CVE-2026-101296` は特定の realm 設定での認証
バイパス、残り2件はデータ混線。

**実務上の難所はパッチではなく、版の把握**です。世の中の Tomcat の大半は Tomcat として
インストールされておらず、Spring Boot や機器、ベンダ製品に**埋め込まれて**いて、
`dpkg -l` には現れません。

```bash
# 単体インストール
/opt/tomcat/bin/version.sh 2>/dev/null | head -3
# 起動中の JVM（Spring Boot 内蔵 Tomcat、fat jar）
java -jar app.jar --debug 2>/dev/null | grep -i "tomcat" | head -3
# 実行中プロセス
jcmd <pid> VM.system_properties 2>/dev/null | grep -Ei "tomcat|server.info"
# パッケージ
dpkg -l | awk '/tomcat/ {print $2, $3}'
```

## 2. Apache HTTP Server 2.4.69 — 「low」なのに 7.5

公開 **2026-10-01**。2.4系で効くのは2件です。

| CVE | Apache のラベル | CVSS (NVD) | 内容 | 影響 |
|---|---|---|---|--|
| `CVE-2026-56154` | low | — | `%{LA-U:HTTP:...}` を使う **mod_rewrite の use-after-free** | 2.4.0 → 2.4.68 |
| `CVE-2026-56449` | low | **7.5** | 細工した応答本文による **mod_proxy_html の範囲外書き込み** | 2.4.68 |

Apache はどちらも **low**、NVD は `CVE-2026-56449` を **7.5** と採点。両方それぞれの前提では
正しく、Apache のラベルは「特定の設定と細工された上流が必要」を、NVD のスコアは「攻撃者の影響下の
入力でそのコンポーネントに到達できる」を表します。**信頼できない上流の手前に mod_rewrite や
mod_proxy_html を置いているなら、自分の露出に合うのは NVD の読み方**です。これは
[`docs/13`](13-recent-criticals.ja.md) §5.1 と同じ罠が、同じベンダファミリの中で1か月のうちに
現れた例です。

## 3. Traffic Server — 2つの経路でリクエストスマグリング

公開 **2026-10-21**、いずれも `security@apache.org` 起票。

| CVE | CVSS 3.1 | CVSS 4.0 | 内容 |
|---|--:|--:|---|
| `CVE-2025-31699` | **8.9** | 9.1 | クライアントが宣言した本文を送り切らないまま（`Expect: 100-continue` 含む）オリジン接続が共有プールへ戻り、その接続の次のリクエストが別の相手に読まれる |
| `CVE-2025-55702` | **8.7** | 7.0 | `Expect: 100-continue` でオリジンが読まなかった本文が**次のリクエスト**として解釈される。接続を共有するフロントプロキシの背後から攻撃可能 |
| `CVE-2026-112381` | 5.9 | 8.2 | チャンク再解析中の half-close でヌルポインタ参照クラッシュ（DoS） |

3件のうち2件は**リクエストスマグリング**——共有コネクションプールを利用者間の通信路に
変えるクラスです。版番号に注意: 2件は `CVE-2025-*` なのに公開は **2026年10月**。開示の遅れは
実在し、「2025 が付いているから古い話」ではありません。

## 5. 実際にやること

1. **Tomcat → 11.0.27 / 10.1.61 / 9.0.123。** インストール版だけでなく**埋め込み**を全部探す。
   認証バイパス1件＋利用者間の混線2件が 2026-10-20 に公開——この表で「今日」なのはこの行です。
2. **httpd → 2.4.69**（mod_rewrite の lookahead、または mod_proxy_html を使っているなら）。
3. **Traffic Server** — CDN/キャッシュ層を運用しているなら2件はスマグリング。修正版は
   プロジェクトの勧告で確認する（「自分のビルドは範囲外」と決めつけない）。
4. **KEV は全部空**（2026-10-22 確認。直近30日で追加された Apache は 2016年の
   `CVE-2016-3081` Struts のみ、しかも遡及追加）。だから任意、ではありません。
   **「まだ誰も悪用を公開していない」＝利用者間データ混線では最初の証拠になりたくない状態**です。
