## Postiz — 2.25.3へ更新

[公式2.25.3リリース](https://github.com/gitroomhq/postiz-app/releases/tag/v2.25.3)は、以下2件を修正し、全ユーザーに即時更新を推奨している（2026-10-24公開）。

| CVE | 影響範囲 | 条件・影響 | 修正 |
|---|---|---|---|
| CVE-2026-115933 | 2.15.0以上、2.25.3未満 | 登録ユーザーによる署名トークン偽造。セッション・招待・パスワード再設定等を混同し、他ユーザーや組織を奪取する可能性 | 2.25.3 |
| CVE-2026-115932 | 2.23.0以上、2.25.3未満 | 登録ユーザーがアップロードディレクトリ外のファイルを読み出す。主経路ではDiscord連携の設定が必要 | 2.25.3 |

出典: [トークン偽造の開示元勧告](https://gadvisory.org/advisories/PSA-2026-YT2HMH)、[ファイル読み出しの開示元勧告](https://gadvisory.org/advisories/PSA-2026-E9AHFV)。

トークン偽造の主経路にはSkoolアカウントとサーバーからapi2.skool.comへの到達が必要。Stripe利用時のプラン条件は組織招待攻撃の一部に関係するが、セッション・パスワード再設定トークンの影響を除去しない。ファイル読み出しの主経路はDiscordの3つの設定値を必要とし、配布docker-composeでは空。一方、別経路もあるため「Discord未使用なので完全に安全」とは判断しない。[各条件は開示元勧告を参照](https://gadvisory.org/advisories/PSA-2026-E9AHFV)。

当面の露出低減として自己登録を閉じる `DISABLE_REGISTRATION=true` が示されている。これは既存アカウントからの攻撃を防がない。ブラウザー拡張を使わない環境で拡張更新経路を制限しても、別の招待経路は残る。更新を優先する。[開示元の回避策](https://gadvisory.org/advisories/PSA-2026-YT2HMH)。

開示元は両件を未改変ビルドで実証したと記載している。これは検証環境での再現であり、実環境の攻撃確認という意味ではない。侵害が疑われる場合は証跡を保全し、漏えいし得る署名鍵・接続先認証情報・アカウントと組織権限を調査する（運用上の推奨）。

## open62541 — OPC UAクライアント側も棚卸し

CVE-2026-116014のCNAレコードは **1.5.0以上1.5.7未満** を影響範囲とする。悪意あるOPC UAサーバーから `UA_Client_getRemoteDataTypes()` を通じて大きなカスタム型定義を読み込むクライアントで、16 bitのmemSizeの整数オーバーフローからヒープ破壊が起こり、停止またはコード実行につながり得る。[CNA原本](https://github.com/CVEProject/cvelistV5/blob/main/cves/2026/116xxx/CVE-2026-116014.json)。

[公式1.5.7リリース](https://github.com/open62541/open62541/releases/tag/v1.5.7)は型サイズのオーバーフロー拒否を変更点として明記する。修正版の公開は8月20日であり、10月24日のCVE採番・公開を「新たに修正版が出た日」と混同しない。関連機能を使うクライアント、組込み製品、静的リンク済み製品について製造元の更新を確認する。CNAのCVSSはv3.1が8.1、v4.0が9.2。確認した一次資料から実環境の悪用は断定しない。

## Apache Traffic Server — 9.2.16 / 10.1.5 / 10.2.1、ただし9.xに例外

10月20日のApache公式告知を10月24日に転送した[oss-secメッセージ374](https://seclists.org/oss-sec/2026/q4/374)で15件を確認した。標準の更新先は9.2.16、10.1.5、10.2.1。多くは9.0.0–9.2.15、10.0.0–10.1.4、10.2.0に影響するが、全件が同範囲ではない。

**重要な例外: CVE-2026-111817は9.2.16に修正を含まない。** 9.2.5–9.2.15では `proxy.config.http.drop_chunked_trailers` を有効化した場合のみ影響し、9.xの既定値は無効。10.xでは既定で有効、10.1.5 / 10.2.1が修正先。「9.2.16で15件すべて解消」と記載しない。9.xで当該設定を有効化している場合は設定を確認し、ベンダーの追加案内に従う。[告知の個別Mitigation節](https://seclists.org/oss-sec/2026/q4/374)。

主な確認項目は以下。すべてが全構成で到達するわけではなく、利用プラグイン、接続共有、TLS設定も照合する。

| 分類 | CVE | 確認すべき条件 |
|---|---|---|
| magick実験プラグイン | CVE-2026-111813 | unsigned既定構成でクライアント引数がImageMagickへ渡る |
| wasm実験プラグイン | CVE-2026-111804 | 10.xのwasmプラグイン |
| リクエスト密輸・キャッシュ汚染 | CVE-2025-31699、CVE-2025-55702、CVE-2026-111809、CVE-2026-111816 | 未読ボディ、Expect、HEAD、応答フレーミング |
| バックエンド枯渇 | CVE-2026-111805、CVE-2026-111808 | 不正HTTP/2入力からHTTP/1.1オリジンへ |
| TLS認証の混同 | CVE-2026-111814、CVE-2026-111815 | 異なるクライアント証明書の接続共有、SNI間のセッション再開 |
| キャッシュ・AWS署名 | CVE-2026-111811、CVE-2026-111812 | tsmemcache / origin_server_authの使用 |
| DoS・停止 | CVE-2026-111810、CVE-2026-111817、CVE-2026-112381 | ログ増幅、trailer破棄、POST half-closeの競合 |

出典: [Apache告知の全文転送](https://seclists.org/oss-sec/2026/q4/374)。111810と112381の対象は9.2.15 / 10.1.4 / 10.2.0。脆弱性の存在・修正公表から、実環境での悪用を推論しない。

## Brotli CVE-2026-111497 — Node.jsだけで調査を止めない

[Google Brotli 1.2.1](https://github.com/google/brotli/releases/tag/v1.2.1)はデコーダの領域外書き込みとRCEリスクの修正を明記する。Cライブラリは1.0.3–1.2.0の範囲に注意し、修正済み分岐は1.0.10 / 1.1.1 / 1.2.1。ディストリビューションのバックポートもあるため、上流版番号だけでベンダーパッケージを判定しない。

| 利用先 | 影響・修正 | 一次資料 |
|---|---|---|
| Bun | 1.0.21以上1.4.4未満。1.4.4へ更新し、`bun build --compile`の実行ファイルも再ビルド | [Bun公式勧告](https://github.com/oven-sh/bun/security/advisories/GHSA-663w-cv8g-jj2p) |
| Python `brotli` | GHSA掲載範囲は1.0.3以上1.2.1未満。1.2.1へ更新 | [GitHub Reviewed勧告](https://github.com/advisories/GHSA-9v8h-qqgm-4m35) |
| Python `brotlicffi` | GHSA掲載範囲は1.0.3以上1.2.1.0未満。1.2.1.0へ更新 | [GitHub Reviewed勧告](https://github.com/advisories/GHSA-9v8h-qqgm-4m35) |

Bunでは自動展開するfetch、node:zlib、DecompressionStreamが入力経路となる。リモートから取得するクライアント処理も棚卸しする。公式勧告はBunに対する攻撃を検証していない旨を明記するため、Bun固有のRCE実証済みとは表現しない。fetchの `decompress: false` はリクエスト単位の回避策で、プロセス全体の解決ではない。[Bun公式の制約](https://github.com/oven-sh/bun/security/advisories/GHSA-663w-cv8g-jj2p)。

Python本体のバージョン更新だけでなく、仮想環境・コンテナごとの追加パッケージと同梱ライブラリを確認する（上記パッケージ勧告に基づく運用上の推奨）。Brotliを「エンコードしているだけ」か「信頼できない入力をデコードする」かも区別する。悪用状態は別途一次情報で追跡し、CVSS値や通称を根拠に実攻撃を断定しない。
