既存の手法と点検可能な例をまとめた資料です。すべての過去スナップショットが同一の処理を使うとは主張しません。
[公開の編集方針](https://www.infosec-briefing.net/about#research-methodology)と

## 収集と来歴

[18:47の収集スクリプト](../tools/intel/snapshot-1847.py)は、
[10:27スクリプトの通信・NVD処理](../tools/intel/snapshot-1027.py)を使用し、固定UTC窓で
NVDの公開と最終改訂を別々に照会します。重大度フィルターは使いません。
NVDは`startIndex`と`totalResults`でページ取得し、GHSAはpublished/modifiedを
reviewed/unreviewed/malware別に照会して`Link`の次ページURLを追います。
失敗・未完了の照会はエラーと完全性フラグを残し、正常な0件へ読み替えません。

[取得マニフェスト](../data/2026-10-27-1847/collection-summary.json)にURL、取得時刻、
ページ、ハッシュ、失敗を記録します。同一内容は過去ディレクトリの原本を参照する場合があります。
参照を別の独立した証拠として複製・加算しません。
[現在のデータへの入口](../data/latest.json)は後続の登録簿とマニフェストを指すポインターで、
不変のスナップショットではありません。

## 一次資料の評価と相互参照

収集・索引生成にはスクリプトがありますが、論点選定と解釈がすべて自動化されているとは確認できません。
開発元の勧告、リリース、公開コード、CNA記録、当事者の公式更新を照合し、二次報道は手がかりとします。
CVE・GHSA IDと参照URLを対応付けますが、常に1対1ではありません。CVEなしのパッケージ勧告もあります。
評価方式、影響版、修正版提供状況の不一致は、出典への帰属を残し、黙って統合しません。

[18:47の研究ノート](research-2026-10-27-1847.md)と
[取得ノート](research-collection-2026-10-27-1847.md)にCNAと開発元の差、本文取得不能の例があります。
一次資料で裏付けられる記述、研究者の報告、未確認の推測を区別します。
実験環境のexploit、修正commit、修正版の出荷、配備、実環境での悪用、復旧は別々の主張です。

## 重複検出と分類

[NVD索引](../data/2026-10-27-1847/nvd-index.json)と
[構造化登録簿](../data/2026-10-27-1847/incident-register.json)にIDと件数を保存しています。
公開・改訂の照会間とNVD・GHSA間でID集合を比較し、重複する件数を新規事件として加算しません。
GHSA内の記録は勧告IDで識別します。CVE集合の照合だけではCVEなしの勧告を扱えません。
Rejectedやunreviewedの状態も保持します。

`delta`、`scope-complement`、`reference-only`は、窓内の更新、過去事案の範囲補完、
時刻等が未確定の参考情報を分ける編集区分です。校正された確度や重大度の点数ではありません。
後続の登録簿には監視状況のラベルもあります。
[10月29日の英語研究](research-20261029T050117Z-dbf8f2.en.md)と
[日本語研究](research-20261029T050117Z-dbf8f2.md)は、保持した過去本文すべてを再精査したわけではないと説明しています。

## 時刻と完全性

発生、検知、公表、DB登録、改訂、調査基準、実取得、修正版提供、復旧を区別します。
UTCの照会窓とJSTの表示は時刻の表現が異なり、inclusiveな境界は隣接窓と重複し得ます。
日付のみ・公表時刻不明の資料に架空の精度を与えません。基準後の取得は取得時点の改訂であり、
基準時刻に存在した本文とは限りません。

ハッシュの対象はマニフェストごとに確認します。10月27日の主収集と補助収集は展開後本文、
当事者資料は保存response byte、広域資料は保存・展開後の両方を計算します。
[10月29日の証拠マニフェスト](../data/20261029T050117Z-dbf8f2/update-infosec-evidence.json)は、
[取得ノート](research-collection-20261029T050117Z-dbf8f2.md)に従いgzip圧縮後を含む保存バイト列を対象とします。
SHA-256一致は記録した値に対する整合性を示すもので、事実の正しさ、上流の真正性、網羅性の証明ではありません。

## 点検と再現

リポジトリのルートでPython 3を使用します。ネットワークや追加パッケージは不要です。

```sh
python3 tools/intel/verify-1847.py
python3 -m unittest discover -s tests -p evidence_manifest_test.py
```

[日付固定の検証スクリプト](../tools/intel/verify-1847.py)は原本ハッシュ、過去原本参照、
ID重複、完全性フラグ、論点数を確認し、派生ファイル`data/2026-10-27-1847/verification.json`を出力します。
[現在の証拠テスト](../tests/evidence_manifest_test.py)は最新ポインターを参照し、証拠ハッシュ、
出典対応、APIページ取得、翻訳の整合性を確認します。証拠と集計の再検証であり、
悪用の再現やすべての報告事象の独立確認ではありません。

再収集は**別checkout**で行ってください。次のコマンドは外部サービスへ接続し、日付固定の保存先へ書き込みます。

```sh
python3 tools/intel/snapshot-1847.py
```

対象はそのスクリプトの固定窓と出典のみです。他の収集には別のパラメーターがあります。
10月29日のノートは`snapshot-1318.py`の再設定を説明しており、全証拠を再生成する単一コマンドではありません。
上流の改訂やAPI制限で応答は変わり得ます。貢献時は過去原本を置き換えず、新旧を比較してください。

## 限界と訂正

対象は選定した出典と成功した取得に限られます。API制限、timeout、redirect、anti-bot、
JavaScriptだけの画面はHTTP成功でも本文確認を妨げます。原記録の留保を保持してください。
修正版不明、公表時刻不明、報告の不一致、未再精査の過去本文は不明のまま扱います。
KEVや本プロジェクトへの未掲載は安全の証拠ではなく、全世界の事件の統計ではありません。
