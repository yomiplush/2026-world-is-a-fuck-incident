## 2. Railway — 環境変数とは、つまり秘密のこと

**一次ソース**: Railway 自身の開示
<https://blog.railway.com/p/security-disclosure-wednesday-october-21st>（2026-10-21、Jacob Cooper）。

Railway が述べていること:

- **顧客の環境変数を保存するシステム**で異常な活動を検知した。
- 不正な第三者が**暗号化された環境変数にアクセスし、一部については復号された内容を取得した
  可能性**がある。
- 環境変数は、まさに API キー・DB の URL・レジストリ資格情報が置かれる場所。
- これは**プラットフォーム企業を狙い、AI 推論プロバイダの侵害を目的とする一連の攻撃の一部**
  と考えており、上流プロバイダにはキーの先制的な失効を依頼した。
- 調査中、**全デプロイを停止**した。
- 初期分析では影響は一部の利用者だが、**全利用者**に資格情報のローテートを求めている。

「全部ローテートしてください」は、こういう事案で最も価値のある一文です。Railway は翌10-22に
資格情報の種類ごとのチェックリストを公開しました。

| ローテート／確認する対象 | Railway の案内 |
|---|---|
| AWS | 不審なアクセスを確認 |
| GCP | 不審なアクセスを確認 |
| GitHub | 不審なアクセスを確認し、資格情報リセット後に再接続 |
| MongoDB / MySQL / Redis | DB 資格情報をローテート |
| Stripe | 想定外の利用を確認 |
| OpenAI / Anthropic / Grok / OpenRouter | 想定外の利用を確認 |
| オブジェクトストレージ | バケットを再デプロイ |

**Railway にデプロイしているなら**: 各サービスの変数に入っている値はすべて侵害されたものとして
扱ってください。忘れているものも含みます（SMTP のパスワード、webhook の署名秘密、`JWT_SECRET`、
セッションキー、外部 API トークン）。DB のパスワードだけ替えて、環境変数に残った S3 キーを
放置するのが、この手の事故の典型的な失敗です。そのうえで該当時間帯のログを読みます。ただし
**盗まれたキーがプロバイダ側で使われても、あなたのアプリログには残りません**。見るべきは
*プロバイダ側のダッシュボード*です。

## 3. OpenCode — 公開されていない侵害と、別件のリポジトリ漏えい

リストでは2つが混ざっています。

**3-1. Console 事案（利用者報告）。** 購読者によれば、**2026-10-17 23:31 UTC** から
`401 api_key_expired` で API キーが失効し、同日から全ワークスペースが制限され、事案は
**「Console breach」**として、サードパーティのプロバイダキーが露出した可能性があると説明されて
います。代表的な報告:

- `anomalyco/opencode#56833` — 「Go 購読者: 有効期限を設定していないキーが失効。Console 侵害に
  ついて正式な補償方針の公開も無い」(2026-10-18)
- `anomalyco/opencode#56703` — 「Console: 10-17 以降すべてのワークスペースが制限。侵害通知メールは
  届いていない」(2026-10-18)

ベンダが公開したもの: **2026-10-22 時点で、このリポジトリが確認できた範囲では何もありません。**
どちらの issue への回答も `help@anoma.ly` へのメール誘導で、公開ステータスページには推論の
遅延・エラー率しか載っておらず、侵害の記録もポストモーテムもありません。したがって正確な状態は
**「影響を受けた利用者からの報告があり、ベンダは非公開でしか応答していない」**です。
リンク無しに「ベンダが確認した」へ格上げしないでください。

**3-2. リポジトリの秘密漏えい（確認済み）。** 別件として `anomalyco/opencode#56819`
（2026-10-18）がソースツリー内の秘密を指摘し、プロジェクト自身の bot が所見を認めています。
コミット `0bedea52b` の `daytona.ts` 15行目に**ハードコードされた Daytona の API キー**、
テストの録画ファイルに Google の API シークレット。利用者データの侵害ではなく衛生管理の失敗
ですが、**サプライチェーン侵害はこういうところから始まります**（[`10`](10-litellm-1-107-0.ja.md) §2 と同じ教訓）。

**OpenCode を使っているなら**: 渡したプロバイダキー（Anthropic / OpenAI / Google / OpenRouter）を
ローテートし、プロバイダのダッシュボードで身に覚えのない利用を確認してください。キーが失効した
ことを「対応完了」としないこと。失効は攻撃者を止め、同時にあなたも止めます。

## 4. 確認できなかったもの

- **"NodeJS and something about broccoli"** — Node.js の部分は
  [`02`](02-nodejs-oct2026.ja.md)（22.23.4 / 24.22.1 / 26.12.1、CA バンドル更新込み）。
  2026年10月の "broccoli" に関する一次ソースは見つかりませんでした。npm の `broccoli` は
  最終更新が 2025-11-11、GitHub Advisory Database にも登録がありません。公開されていない
  何かを指しているか、まったく別のネタか。**推測で埋めず「未確認」として記録します。**
- **"The number 4"** は確認済みですが、確認できたのは「値が 4 の証明書が存在する」ことではなく、
  **秘密鍵が整数 4 だった**ことです。[`03`](03-emudhra-ca.ja.md) §2 参照。

## 5. で、結局これ何なのか

7つの無関係な出来事に見えて、実は**2つの群と1本の糸**です。

- **従来型の脆弱性対応**（1、6）: 広く使われるランタイムやサーバのメモリ安全系のバグ。
  パッチを当て、版で確認する。未適用のホストが長く残る。
- **信頼の材料**（3）: PKI。トラストストアを更新して失効させる。
- **資格情報の窃取**（2、5、7）: 今週を定義しているのはこの群です。Railway は
  *「プラットフォーム企業を攻撃して AI 推論プロバイダに到達する」*と明言し、残り2件も同じ形。
  多数のプロバイダキーを持つ AI ゲートウェイ（LiteLLM）と、Console にプロバイダキーを
  持っていた AI コーディングツール（OpenCode）。

糸は、**2026年に価値があるのは「箱」ではなく「鍵」**だということです。RCE で得られるのは
ホスト1台。盗まれた `ANTHROPIC_API_KEY` やクラウドのロールから得られるのは、請求書とデータと、
**検知すべき exploit が無いまま AI パイプラインの内側に居座る位置**です。7件のうち3件は、
3つの別の鍵置き場に対する同じ攻撃です。

実務的には、作業の順番が変わります。

1. **プロバイダキーを保持しているシステムを棚卸しする**。Railway の環境変数、LiteLLM などの
   ゲートウェイ、AI コーディングツール、CI の秘密。これらを最重要資産として扱う。
2. **証明ではなく疑いでローテートする**。資格情報窃取では「証拠が無い」が通常の初期状態です。
   Railway は証拠を待たずにデプロイを止め、利用者に鍵のローテートを求めた。
3. **アラートは「保管場所」ではなく「使用地点」に置く**。プロバイダのダッシュボード（支出・利用の
   異常）、クラウドの監査ログ（`GetCallerIdentity`、`AssumeRole`）、リリースワークフローに対する
   GitHub の監査ログ。
4. **同じ手口は繰り返される前提で。** LiteLLM は7か月で2回、同じ `.pth` で侵害されました。
   この環境で実際に効いた対策は、版の固定とハッシュだけです。
