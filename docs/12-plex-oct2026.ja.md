# Plex Media Server — 5件のCVE、文書化された連鎖、そして期限が今日のKEV

[English](12-plex-oct2026.md) | [**日本語**](12-plex-oct2026.ja.md)

Plex は **CISA KEV 入り**しています。このリポジトリで「実際に誰かが使っている」を意味する
主張はこれだけです。KEV への追加は **2026-10-20**、うち2件の期限は **2026-10-23**——
スナップショット時点で読むなら明日です。

以下は CISA 自身の機械可読アドバイザリ
（[`data/2026-10-22/csaf-va-26-266-01.json`](../data/2026-10-22/csaf-va-26-266-01.json)、
CISA CSAF **VA-26-266-01**）、NVD のレコード、KEV の項目に基づきます。Plex のフォーラム告知は、
機械可読ソースに無い情報がある箇所だけ引用します。

## 1. 5件のCVE

5件すべて、修正版は同じビルド **Plex Media Server 1.43.3.10861**（Plex Desktop 1.115.0）。
CISA が VA-26-266-01 を公開したのは **2026-09-23** で、CVE が NVD に載ったのと同じ日——Plex 自身の
告知（2026-09-01）が「CVE を申請中」とだけ述べていた3週間後です。この順序が要点で、その3週間は
「修正版」はベンダページから分かるのに、権威ある技術的説明は CSAF と NVD にしか無い状態でした。

| CVE | 内容 | CVSS 3.1 | CVSS 4.0 | 前提 | KEV |
|---|---|--:|--:|---|---|
| `CVE-2026-96651` | `/system/agents/media/get` のパストラバーサル。そのユーザーが読める任意のファイル、**`PlexOnlineToken` を含む** | 6.5 | 7.1 | 有効なセッショントークン（`X-Forwarded-For` で LAN 隣接からも） | — |
| `CVE-2026-96652` | `/player/timeline` の SSRF。`protocol` に URL を入れるとサーバがそこへ POST する | 4.3 | 5.3 | **任意の** `X-Plex-Token` | **あり**、期限 2026-11-03 |
| `CVE-2026-96654` | `searchOne` が URL 値を中和せず、他プラグインの関数を任意パラメータで呼べる | 6.5 | 6.9 | なし（未認証） | **あり**、期限 2026-10-23 |
| `CVE-2026-96655` | `/video/:/transcode/universal` のパスパラメータ経由の SSRF | 4.3 | 5.3 | 認証済みユーザー | **あり**、期限 2026-11-03 |
| `CVE-2026-96656` | 管理者が設定した `TranscoderH264Options` が x264 のオプション文字列にそのまま連結される。加えて起動時に**全 `.so` を署名・実行ビット・シンボル検査なしで実行**する | 7.2 | 8.6 | 管理者 | **あり**、期限 **2026-10-23**、フォレンジックトリアージ必須 |

最後の行を正確に読んでください。「管理者がファイルを書ける」ではありません。**管理者が書いた
ファイルを、サーバが次回起動時に、完全に無検査で実行する**という意味です。だから下の連鎖が
成立します。

## 2. 主役はスコアではなく連鎖

CISA の KEV の説明が明言しています: `CVE-2026-96656` は `96652` / `96654` / `96655` と
**連鎖可能**。前提条件の順に並べると:

```
任意の X-Plex-Token（96652）
      ↓  サーバが処理するエンドポイントへの SSRF
未認証でプラグイン関数を呼ぶ（96654）
      ↓  内部サービス／任意ホストへ到達（96655）
管理者権限でのファイル書き込み（96656）
      ↓
次回起動時に任意コード実行
```

個々のスコアは平凡です——4.3、6.5、7.2。連鎖は完全侵害で、その入口は**共有ユーザー、クライアント
アプリ、外部ツールの多くが持っているトークン**です。これが「CVSS だけでトリアージするな」の
具体的な反例になります。表のどの行も 7.2 を超えていないのに、KEV の条件はすでに満たしています。

KEV に入っていない `CVE-2026-96651` は、単体では最も被害が大きい可能性があります。
`PlexOnlineToken` を読めれば Plex **アカウント**とサーバを掌握でき、ホスト1台を超えた永続化に
なります。NVD の記録は、`X-Forwarded-For` を偽装した LAN 隣接の攻撃者でも到達可能と注記して
います。読み方は2つ——SSRF 群より武器化が難しいのか、単にまだ観測されていないのか。いずれにせよ
「KEV に無い＝安全」ではないので、同じパッチの4件目として扱ってください。

## 3. スコア以上に気にすべき理由

- **Plex は意図的に公開されることが多い。** Remote Access は 32400 を UPnP/NAT-PMP で通し、
  「外から見える」ことが機能として案内されています。家庭用機器がインターネット公開サービスに
  変わり、4.3 の SSRF とトークンだけの経路がちょうど効く条件が揃います。
- **トークンは希少ではない。** `X-Plex-Token` は全クライアント、共有ユーザー、連携ツール
  （Tautulli、Overseerr、*arr 系）に配られます。「トークンが必要」は Plex 世帯では低い壁です。
- **パッケージ管理は遅れ、Plex 自身がそう書いている。** 告知は NAS のパッケージ管理に
  1.43.3 がまだ無い可能性を警告し、手動インストール手順を示しています。Synology/QNAP の
  ユーザーがストアを待つと、その間は露出したままです。
- **未認証 RCE は不要。** KEV が追っているのは「地味な」バグの連鎖で、実際の侵入はたいてい
  そういう形をしています。

## 4. 該当するか、何をするか

```bash
# 1) 版（Settings → General でも見える。API はトークンが必要）
curl -s "http://127.0.0.1:32400/identity" | tr '>' '>\n' | grep -i version
#    影響: 1.43.3.10861 より前

# 2) インターネットから届くか（外側から確認）
curl -s -o /dev/null -w '%{http_code}\n' "https://<自分のドメインかIP>:32400/identity"

# 3) 更新
#    Synology/QNAP など: ストアが遅れる → ベンダのパッケージを手動導入
#    Docker（linuxserver/plex、plexinc/pms-docker）: 1.43.3.10861 を含むタグへ
docker pull plexinc/pms-docker:latest && docker compose up -d
```

未修正のまま露出していた可能性があるなら、次の順で:

1. **アカウントのトークンをローテート。** Plex で全デバイスからサインアウト、またはパスワード
   変更（既存トークンが無効になる）。その後クライアントを再認証。`PlexOnlineToken` は
   侵害されたものとして扱う——それが `96651` の読み取り対象です。
2. **サーバの永続化を確認。** `96656` は起動時に `.so` を実行します。Plug-ins / Codecs と、
   Plex データディレクトリ配下で説明のつかない更新時刻のファイルを確認。CISA はこの CVE を
   `Forensics Triage: Yes` と指定しており、BOD 26-04 の文脈では「パッチだけでなく証拠保全」
   を意味します。
3. **露出を閉じる。** リモートアクセスが不要なら無効化。必要なら VPN か認証付きリバースプロキシ
   の内側に置き、32400 の直接ポート開放をやめる。
4. **アカウントを確認。** 見覚えのない共有ユーザー、ライブラリ、デバイスを確認。`96651` の
   狙いはまさにアカウント乗っ取りです。

## 5. 言ってはいけないこと

- 「4.3 だから低優先」。その低いスコアは、KEV が追っている連鎖の**入口**です。
- 「管理者権限が要るから大丈夫」。`96656` は管理者、`96652` は全クライアントが持つトークン。
  連鎖が成果物です。
- 「`96651` は KEV に無い」で終わる。あれはアカウント掌握に直結するトークンを読みます。
- NAS ユーザーに「ストアから更新すればいい」と言う。ベンダ自身がストアの遅れを警告しています。
