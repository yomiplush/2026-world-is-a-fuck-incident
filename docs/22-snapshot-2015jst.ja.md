## 2. Node2Shell — X の1投稿から、公式ビルドでのコード実行まで

この回の出発点になった項目で、裏が取れました。経路はこうです: X の投稿（2026-10-23 07:51 UTC）
→ 業界紙の記事 → ベンダの研究記事（2026-10-22 12:22 UTC）→ Node.js の勧告（2026-10-21）
→ NVD → Brotli 上流の修正。5つのうち4つは一次ソースです。

| 時刻（UTC） | 出来事 |
|---|---|
| 2026-10-21 | Node.js が `CVE-2026-111497` を公表し、**22.23.4 / 24.22.1 / 26.12.1** を公開 |
| 2026-10-22 12:22 | Imperva が「Node2Shell」を公開。**公式の 24.22.0 Linux arm64 イメージ**で、デバッガも計測ビルドも無しにコード実行 |
| 2026-10-23 07:51 | The Hacker News が X で警告 — 私たちに届いた導線 |
| 2026-10-23 11:20 | NVD の24時間スイープに記録が出現: `Awaiting Analysis`、CVSS 4.0 **9.2**、CVSS 3.1 無し |

### 2.1 実証が示したこと、示していないこと

示したこと: 細工した Brotli データが Node.js 同梱のデコーダに届き、対象プロセス内で実行される
（マーカーファイルを作るコードを持たないアプリに、そのファイルが現れた）。修正版は**同じ入力を
拒否する**。検証は1つのビルド（24.22.0、Linux arm64）で、成功まで複数回の試行を要し、
Express 5.0.0〜5.3.0 と body-parser 2.0.0〜2.3.0 は固定した版のみ（中間の全リリースは未検証）。

示していないこと: 22.x / 26.x、他のアーキテクチャでの成立。そして、最初の公開 PoC の
「クラッシュ＋限定的なメモリ読み出し」がコード実行だったこと — そうではなく、Imperva 自身が
そう書いています。

`CVE-2026-111497` の実環境での悪用報告はありません。**配布ビルドに対する実験室の結果**である
ことが、「今週」を「今日」に変える理由です。

### 2.2 到達経路を正確に — `docs/02` の丸めを訂正します

[`docs/02`](02-nodejs-oct2026.ja.md) は「HTTP サーバが `Accept-Encoding: br` を扱うなら、
未認証のリクエストで到達し得る」と書いています。これは粗すぎます。範囲の見積もりに効くので
訂正します:

| 経路 | 必要なもの | 未認証で到達するか |
|---|---|---|
| 応答の消費 | 自分のコードが、攻撃者の影響下にある URL に対して組み込み `fetch()` を呼び、応答が Brotli 圧縮 | する — 応答そのものが入力 |
| リクエストボディ | Brotli を**展開する**パーサ: Express 5 の `express.json()` / `urlencoded()` / `text()` / `raw()`、または `body-parser` 2.x を直接 | そのルートでは、する |
| 素の `http.createServer()` | 受信ボディを自動で展開するものは無い | しない（アプリ自身が Brotli を解かない限り） |

つまり問いは「HTTP を出しているか」ではなく、**「信頼できない Brotli がデコーダに届くか」**
です（HTTP 交換のどちら側でも）。両方の経路は同じネイティブ関数で終わり、同じランタイム更新で
直ります。

### 2.3 何をすればいいか

- **ランタイムを更新**: 各ラインで 22.23.4 / 24.22.1 / 26.12.1 以降。**コンテナイメージと、
  Node バイナリを同梱する成果物も含めて** — パッケージ棚卸しでは見落とします。
  `tools/node/nodefix-audit` が列挙します。
- **20.x は EOL** で何も来ません。ランタイム内の回避策はありません。Imperva の提案は
  「更新**しながら**、影響経路の信頼できない Brotli を制限する」であって、更新の代替ではありません。
- この CVE 向けの WAF ルールは既にあります（Imperva は自社ルールを検証済み）。時間を買うだけで、
  デコーダは消えません。
- 相関の話であって、検知ではありません: 展開中の予期しないプロセス終了やデコーダの形式エラーは
  見る価値がありますが、どちらも単独では悪用の確実な兆候になりません。

### 2.4 なぜ深刻度スイープが取りこぼしたか

レコードは `cvssMetricV40` 9.2 を持ち、**`cvssMetricV31` を持ちません**。
[`docs/13`](13-recent-criticals.ja.md) を作る NVD クエリは CVSS 3.x の深刻度で絞ります。
そのため、その日の悪用済み Node の脆弱性は CRITICAL 一覧に出ません。Arista の 9.9 も同じです
（3.1 のスコアが `Secondary`＝CNA のものだけ）。**今日もっとも重い3件のうち2件が、最も権威に
見えるフィルタに見えていませんでした。**

全深刻度の公開スイープ（342行）とベンダのフィードは、両方とも拾っています。広くて絞らない
スイープを既定の取得に残す実務的な理由は、これです。

## 6. 方法: この回の代償と収穫

- **チャネルは根拠ではないが、唯一の早期警報です。** X の投稿と業界紙を収集対象に加えました
  （`x-posts.json`、`news-feeds.json`）。どちらのファイルにも「引用するのは投稿ではなく、
  その中のリンク」と書いてあります。ニュース経由で見つかった §4 の4件は、その日のどの CVE
  フィードも名指ししていませんでした。
- **空の列も主張です。** 今回の `with_epss` は **0/342**。正直な読みは「EPSS は 2026-10-22 の
  モデル実行以降に公開されたものにスコアを付けていない」であって、「スコアが0」ではありません。
  収集ツールは拒否されたバッチを別に記録するようにしました（`epss_batches_failed`）。429 が
  「スコアが無い」に化けないようにするためです。[`docs/08` §5](08-intel-sources.ja.md) と同じ原則:
  **時刻と適用範囲を添えない数字は、自分自身と矛盾します。**
- **2つのフィルタは、設計上ずれます。** NVD の深刻度フィルタは自分（Primary）の CVSS 3.x だけを
  数え、公開日スイープとベンダフィードは誰のスコアか気にしません。両方を持ち、「何が悪用されて
  いるか」を問うときは絞らない方を読みます。今日の差は具体的です: 悪用された Node と Arista は、
  どちらも絞ったクエリでは0件でした。
- **24時間前の CVE に解析は無いのが普通です。** 342件公開、`Analyzed` **0**、CPE マッピング
  **0/342**、CVSS 3.1 が 244件、CVSS 4.0 が 179件。壊れているのではなく、待ち行列が
  ニュースサイクルより長いだけです。

**デッキ。** 上の4件は `site/` のタップ送りブリーフィングのシーン21〜24（`node2shell`、
`prepatch`、`filters`、`wide`）になっています。それぞれ専用のモーショングラフィックと出典
ドロワー付き。デッキは全25シーンになり、表紙とメタ情報も更新済みです。
