## Editorial priorities

- **Apache Shiro (8 advisories across `3.0.1` and `3.0.2`):** Eight Openwall `oss-security` disclosures cover authentication caching, session fixation, annotation enforcement and filter routing. In particular, enabling `authenticationCachingEnabled = true` on `DefaultLdapRealm` causes cached credentials to be checked with the default `AllowAllCredentialsMatcher`, accepting any password after an initial successful LDAP bind (`CVE-2026-129349`, CVSS 4.0 9.1, fixed in `3.0.1`), and RememberMe authentication reuses pre-login session IDs (`CVE-2026-74762`, fixed in `3.0.1`). Six further issues—unenforced interface/superclass annotations in `shiro-guice`, `shiro-aspectj`, `shiro-cdi` and `shiro-jakarta-ee` (`CVE-2026-74763`), saved-form POST replay in `shiro-jakarta-ee` (`CVE-2026-88019`), case-sensitive path matching on manually registered `ShiroFilterFactoryBean` beans in `3.0.1` (`CVE-2026-114737`), empty stored credential acceptance (`CVE-2026-129347`), stale privileges after `PropertiesRealm` reload (`CVE-2026-129348`), and unescaped `shiro:principal` JSP tag output (`CVE-2026-129320`)—are fixed in `3.0.2`. Upgrade directly to **`3.0.2` or later**.
- **Perl `JSON::XS` (7 CVEs) and `HTTP::Session` / `Dancer`:** `JSON::XS` `< 4.05` fixes a 1-byte heap OOB write in `incr_parse` (`CVE-2026-129114`), 32-bit `incr_skip` offset wraparound (`CVE-2026-129113`), post-NUL `max_size` bypass (`CVE-2026-124536`), freed-stack read via `FREEZE` under `allow_tags` (`CVE-2026-129115`), `allow_tags` recursion stack exhaustion (`CVE-2026-124540`), and two memory leaks on rejected JSON (`CVE-2026-124539`, `CVE-2026-124541`) in version `4.05`. Retroactively assigned historical flaws in `HTTP::Session` `< 0.43` (Memcached CRLF injection `CVE-2011-10042`, fixed in `0.43`, module deprecated in `0.54`) and `Dancer` `< 1.3400` (unvalidated session ID in `read_session_id` `CVE-2015-10149`, fixed in `1.3400`) are separated by affected version and lifecycle status.
- **FRRouting `bgpd` (`CVE-2026-129456`) and Ettercap (`CVE-2026-129431`, `CVE-2026-129432`):** In FRRouting `bgpd`, a BGP UPDATE carrying a Tunnel Encapsulation attribute (Attribute 23) with a mismatched outer TLV length leaves sub-TLV reference counts unbalanced, causing a double free and BGP session drop on route replacement or withdrawal (fix commits `abef07b5` and `bebf95f0`). Ettercap `<= 0.8.5.1` heap OOB reads in `dissector_socks()` and `dissector_mountd()` have upstream pull requests (`#1340`, `#1341`) but no fixed release version listed in NVD.
- **Dokploy (`CVE-2026-129433`) and Pulse (`CVE-2026-129428`):** Dokploy `< 0.31.1` concatenates unsanitized `serviceName` values into `/bin/sh -c` in `getComposeContainerCommand()`, allowing authenticated members to execute arbitrary commands as `root` on the Dokploy host (fixed in `0.31.1`). Pulse `5.0.17` through `< 6.8.0` lacks role authorization checks on `/api/ai/approvals`, allowing read-only `viewer` users to list, approve or deny AI tool-execution requests (fixed in `6.8.0`).
- **NLTK 3.10.4 (3 published reviewed advisories + 2 modified withdrawn duplicates):** All three GHSA reviewed advisories published in this window (`CVE-2026-126299` `nltk.ccg.lexicon.fromstring`, `CVE-2026-126298` `Tree.chomsky_normal_form()`, `CVE-2026-126297` `ConllCorpusReader.srl_instances()`) affect `<= 3.10.3` and are fixed in `3.10.4`. Two duplicate advisories marked `withdrawn_at` in the modification window (`GHSA-6665-2vj3-h76r`, `GHSA-qvhx-rvgc-jhwf`) are not double-counted as active vulnerabilities.
- **Vim `ps1.vim` incomplete fix and media parsers (GPAC, `libdca`, `sox_ng`):** Vim `< 9.2.1346` leaves typographic single quotes (`U+2018`–`U+201B`) unescaped in `runtime/ftplugin/ps1.vim` when invoking `Get-Help` via Visual-mode `K` (incomplete fix for `GHSA-r5v6-q6j8-8qw2`, patched in `9.2.1346`, no CVE assigned yet). GPAC `<= 26.07.0` XMT parser flaws (`CVE-2026-124030`, `CVE-2026-124031`, `CVE-2026-128240`; commits `1359c4da`, `43a8329a`, `a2e5c62c` with no release version listed), unmaintained VideoLAN `libdca` `HEAD 95c4bd8` scale-factor OOB read (CVE pending, no upstream patch), and `sox_ng <= 14.8.1` VOC decoder OOB write (`CVE-2026-129264`, commit `0b40408b`) keep their exact patch states explicit.
