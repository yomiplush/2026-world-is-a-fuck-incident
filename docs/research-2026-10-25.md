## 10月24日公表・更新の重要な差分

### Oracle Java / eMudhra：ブラウザー更新だけでは足りない

Oracle は **10月24日 Rev 1** の緊急勧告 `CVE-2026-114820`（CVSS 3.1 **9.1**）で、eMudhra に関係する影響ルート証明書を Java の trust store から除去する更新を公表。対象表には Java SE **8u511-b32 / 8u511-perf-b32 / 11.0.33.0.2 / 17.0.21.0.2 / 21.0.13.0.2 / 25.0.5.0.2 / 27.0.1.0.2**、GraalVM for JDK **17.0.21.0.2 / 21.0.13.0.2**、GraalVM Enterprise **21.3.20.0.2** を記載。**これらは「影響版」の欄であり、修正版として配布しない**。最新 Java 更新または公式の緩和を適用する。[Oracle 緊急勧告](https://www.oracle.com/security-alerts/alert-cve-2026-114820.html)

10月24日更新の公式運用手順は、更新不能なら keystore をバックアップし、`emsignrootcag1 [jdk]`、`emsignrootcag2 [jdk]`、`emsigneccrootcag3 [jdk]`、`comodoaaaca [jdk]` の4ルートを削除し、**生存中の各 Java ランタイムを再起動**する手順を提供。複数インストールはそれぞれ対応する。代替の失効チェック設定、署名 JAR 検証、JDK 8 以降用 `CheckCerts.java` もある。アプリ同梱JRE・コンテナ・独自 trust store は実際に利用する証明書ストアを確認する。[Oracle ops.java 手順](https://ops.java/emudhra)

### ConnectWise Cloud Backup：復旧目標と再接続許可を区別

公式 **10月24日 14:00 UTC** 更新は、Cloud Backup（旧 SkyKick）のアプリ資格情報への不正アクセスを確認し、証明書ローテーションと安全性検証を継続。**10月26日から段階的に再開する目標**であり確約ではない。対象接続は個別の正式手順が出るまで無効のまま維持する。既存バックアップは暗号化・隔離・保全され、侵害の兆候はないとベンダーが説明。これは全顧客テナントの無被害を証明しない。Axcient Legacy Portal の PHP 対応と10月22日の復旧は、この侵害とは別件。[ConnectWise 公式更新](https://www.connectwise.com/company/trust/advisories)

ベンダー技術手順（10月18日）は **7つの Application ID** を掲載し、休眠接続を含め顧客テナントごとの確認を要求する。ベンダー側失効は顧客側 enterprise application の設定変更を意味しない。最初にアプリを削除せず、無効化・設定保存・監査ログ確保を行う。調査は10月13日以降、可能なら10月1日まで拡大。資格情報、所有者、同意・権限、条件付きアクセス、メール転送等の残存変更も確認する。[公式15ページ手順](https://www.connectwise.com/contentassets/10777cd3364d440c86ed5270a94a5f24/connectwise-cloud-backup-technical-investigation-and-remediation-guide-1.pdf)

## 実被害・攻撃観測の読み替えを防ぐ更新

### Microsoft：ConnectWise に関係する攻撃を一次で確認

Microsoft の **10月21日** 報告は、Storm-0940 による ARTEX 利用と、複数の顧客環境での不正なアプリ認証後の Graph 操作・資格情報変更・権限変更を記載。**2,250超のテナントへのサインイン試行は、2,250件の侵害確定や漏えい確定ではない**。別の password spray の **151,000超の失敗ログ**については、成功認証・トークン発行・Graph操作を観測しなかったと明記。帰属は Microsoft の評価。過去資料の「一次未確認」はこの報告について解消できる。[Microsoft 一次報告](https://www.microsoft.com/en-us/security/blog/2026/10/21/storm-0940-uses-artex-agentic-ai-connectwise-supply-chain-compromise/)

### LiteLLM：初期推定より10月23日の確定経路を優先

**10月23日**の公式確定報告は、5月27日に公開リポジトリへ誤って置いた Agent Platform の master key が**未失効**だったこと、10月10日に攻撃者がそこから organization owner の GitHub CLI OAuth token を取り出し、追加 CI secrets を取得し、リリース制御を迂回した経路を記載。初期状況報告の「最近修正した脆弱性が原因か」とする推測を確定原因として再掲しない。ソースから秘密を消すだけでは失効しない点が対策上の要点。[LiteLLM 確定報告](https://docs.litellm.ai/blog/security-incident-oct-21-2026-attack-chain)

対象は10月21日 PyPI **1.107.0 の7 wheels**（11:39:51–13:23 UTC）、Docker Hub の `v1.107.0 / latest / main-latest / main-stable`（11:46:56–14:20 UTC）、GHCR の対象 digest（11:46:56–13:51 UTC）。GitHub ソースタグ自体には悪性ファイルがない。Python 起動時フックのため **LiteLLM を import しなくても起動し得る**。対象環境で調査のために pip を先に実行しない。隔離・証拠保存・クリーンな環境から再構築し、到達可能だったクラウドロール、AI API、DB、proxy master/virtual key 等を失効・更新する。削除済みマーカーの不在は無被害の証拠ではない。[LiteLLM 対象と復旧手順](https://docs.litellm.ai/blog/security-incident-oct-21-2026)、[Microsoft 独立解析](https://www.microsoft.com/en-us/security/blog/2026/10/23/inside-the-litellm-1-107-0-supply-chain-compromise-credential-theft-through-python-startup-hooks/)

### PHP2Shell：ログ調査は10月17日まで遡る

AWS の10月21日付一次報告は、MadPot で **10月17日**に悪用試行を観測し、公表前の10月21日02:00–08:00 UTCにも複数の試行を確認。AWS は当該 payload の実環境での成功可能性を分析中としており、試行数を侵害成功数に読み替えない。調査開始点は少なくとも10月17日とする。`PHP_SESSION_UPLOAD_PROGRESS` を含む POST、不審プロセス・ファイル変更等を照合する。掲載 IP は共有匿名化基盤を含み、IP一致だけで断定しない。更新以外の設定だけで2件全てを解消できるとはしていない。[AWS 一次報告](https://aws.amazon.com/blogs/security/amazon-threat-intelligence-identifies-php2shell-exploitation-prior-to-public-disclosure-in-madpot/)

### Unbound：1.26.2、5件をまとめて確認

## Brotli：Node.js という製品名だけで棚卸ししない

`CVE-2026-111497` は Brotli の境界外書き込み。Google **1.2.1** は10月21日に修正を公開。OSパッケージ、vendored/staticなコピー、ランタイム、コンパイル済み実行物を別々に確認する。[Google リリース](https://github.com/google/brotli/releases/tag/v1.2.1)

**Bun** の10月23日公式GHSAは **>=1.0.21, <1.4.4** を対象とし、**1.4.4**へ更新、`bun build --compile` で作った実行物も再ビルドするよう指示。`fetch` の upstream `Content-Encoding: br` 自動展開、`node:zlib`、`DecompressionStream` が経路。Bun でRCE攻撃を試験したとはしていない。`fetch({decompress:false})` は各リクエストだけの緩和で、他APIを保護しない。[Bun 公式GHSA](https://github.com/oven-sh/bun/security/advisories/GHSA-663w-cv8g-jj2p)

**Node.js** の10月21日セキュリティリリースは22/24/26系列のBrotliに加え、DNSのNUL、IPv4表記とTLS hostname検証等も対象。悪性 upstream 応答の展開も棚卸しし、圧縮したレスポンスを配るだけのサーバーと分けて判断する。[Node.js 公式勧告](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases)

**Debian trixie** は10月23日 DSA-6582-1 で **brotli 1.1.0-2+deb13u1** を修正版とする。上流1.2.1未満という文字列比較だけで未修正判定しない。OS更新はPyPI wheelや静的リンク済みアプリを自動修復するとは限らない。[Debian DSA](https://lists.debian.org/debian-security-announce/2026/msg00498.html)
